# 登記書類整合性審査機能 開発進捗報告書

**日付**: 2026 年 7 月 31 日
**対象**: 抵当権設定案件の登記書類整合性審査（提案デモ用）

---

## 1. 目的

現在ご評価いただいている AgentCore harness は、事前抽出済みの OCR データ（JSON）を入力として、登記書類の整合性審査を高精度に実行しています。本取り組みでは、**スキャンされた PDF/画像をそのまま入力**として受け付け、システム上の案件データとの整合性を審査できるよう、本プロジェクトのマルチモーダル LLM 機能を拡張します。これにより、OCR 前処理なしに harness と同等の審査を実現し、提案の技術的根拠を示します。

## 2. 利用方法の変化（新しい使い方）

本拡張により、審査の対象と入力方法が以下のように変わります。本プロジェクトの現行レビュー機能（`review-item-processor`）をご存知の方にも、イメージを持っていただくための説明です。

**従来（現行のレビュー機能）**
- 審査対象は **1 つのファイル**（PDF または画像）。
- チェックリストは、そのファイル内の確認事項を検証。

**今回の拡張後の流れ**

1. **チェックリスト（比較ルール）の用意**: 審査で用いる比較ルールは **事前に作成し、システムに取り込んで（登録して）おきます**。既存の「文書からの自動生成」機能も引き続き利用可能です。
2. **複合データの入力**: 審査対象として、以下の **複合データ** をアップロードします。
   - **複数の書類スキャン**: 文書の種類（文書タイプ）ごとに 1 件ずつ、PDF/画像。
   - **案件データ（JSON）**: システム上の関連情報で、項目名と値がいずれも自然言語で記述されたデータ。
3. **審査の実行**: 取り込んだチェックリストに基づき、**書類同士の整合性** と **書類と案件データの整合性** を判定します。

**比較の例**
- 「抵当権設定契約証書の債務者氏名」と、案件データの「顧客氏名」が一致するか。
- 「登記簿謄本の地積」と、案件データの「土地面積」が一致するか。
- 「抵当権設定契約証書のご契約日」と「登記簿謄本（乙区）の原因日付」が一致するか（和暦・西暦の変換を含む）。

この利用イメージは、harness が JSON 入力で行っていた審査（書類の OCR 結果と案件データの比較）を、**スキャン文書そのものを入力として**行えるようにしたものです。

## 3. harness との対比（本方案の優位性）

| 観点 | 現行 harness | 本方案（本プロジェクト拡張） |
|---|---|---|
| 入力形式 | 事前抽出済み OCR データ（JSON） | スキャン PDF/画像を直接入力 |
| OCR 前処理 | 別途必要 | 不要（マルチモーダル LLM が文書を直接読取） |
| 審査方式 | システムプロンプト ＋ 比較ルール | 同等（17 の比較ルール、3 状態判定） |
| 適用範囲 | 抽出済みデータに対する審査 | スキャン文書から一気通貫で審査 |

最大の差異は、**harness が受け付けられなかった PDF/画像の直接入力を、本プロジェクトのマルチモーダル LLM で実現する**点にあります。OCR 前処理パイプラインに依存せず、書類そのものから審査までを行えます。

## 4. 審査の対象範囲（登記デモ）

- **文書タイプ（4 種）**: 抵当権設定契約証書 / 登記完了証 / 登記情報識別通知 / 登記簿謄本
- **比較ルール（17 件）**: 書類間、および書類と案件データ間の整合性照合（氏名・金額・利率・日付・住所など）
- **判定（3 状態）**: 一致（✅） / 不一致（❌） / 判定不能（⚠️：データ欠損を明示的に区別）

## 5. 進捗：決定論的基盤が完成・検証済み

LLM の呼び出しに依存しない「決定論的（ルールベース）」な部分、すなわち精度を左右する正規化・ルール選別・結果集計などを完了し、自動テストで検証しました。この層はクラウド環境を前提とせず開発機で確実に検証できるため、品質リスクを低く抑えています。

**定性実績**
- harness が備える「表記揺れの正規化」ルールを決定論的に実装：和暦↔西暦変換（元年・全角数字対応）、金額のカンマ区切り/非区切りの同一視、利率の全角/半角「％」の同一視、氏名のスペース除去。
- 複合データ入力に対応するデータモデル拡張：文書タイプ付きスキャン＋案件データ（JSON）を取り扱う仕組み。
- 3 状態判定と、親項目（総合審査）への結果反映ルール（不一致 ＞ 判定不能 ＞ 一致）を実装。
- 各比較ルールが参照する文書だけを LLM に投入する仕組み（不要な文書を読ませない＝精度向上とコスト削減を両立）。

**定量データ**

| 指標 | 値 |
|---|---|
| 自動テスト数（合格） | **118 件**（Python 70 / バックエンド 48） |
| クラウド環境なしで検証済みの層 | 決定論的ロジック全体 |
| 審査ルール数 | **17 件** |
| 対応文書タイプ | **4 種** |
| 実装した正規化ルール | 和暦↔西暦・金額・利率・氏名・日付比較 |

## 6. 次のステップ

- マルチモーダル LLM（Amazon Bedrock）と結合し、実際のスキャン文書を用いた **動作検証** を進める（harness との比較も視野に入れ、判定結果を確認していく）。
- 審査実行パイプライン（Step Functions）およびフロントエンド画面（文書アップロード・結果表示）の完成。
- ※ LLM を用いた判定の検証は、LLM 実行環境にて順次進める予定です。

## 8. まとめ

精度に直結する決定論的基盤は完成し、118 件の自動テストで検証済みです。LLM との結合により、harness と同等以上の審査をスキャン文書から一気通貫で実現し、提案用のデータを提示できる状態が整いつつあります。
